# System Architecture Diagram & Topography

## 1. Network Topography

[ External Web/Mobile Clients ]
           │
           ▼ (HTTPS / WSS)
[ Go (API Gateway & Load Balancer) ] ──▶ [ Java (Enterprise Webhook Service) ]
           │
           ├─▶ (gRPC) ─▶ [ Python (AI Inference Engine) ]
           │
           └─▶ (REST) ─▶ [ TypeScript/Next.js (Web Frontend via Vercel) ]

## 2. Asynchronous Data Pipeline (Internal Network)

[ Target Websites ] 
    │
    ▼
[ Ruby (Scraper) ] ──(AMQP)──▶ [ Message Broker (RabbitMQ) ]
                                   │
                                   ▼
[ Rust (High-Speed Tokenizer) ] ──(TCP/IP)──▶ [ Supabase (PostgreSQL) ]
                                                    ▲
                                                    │
[ R (Statistical Analyzer) ] ───────────────────────┘

## 3. Database Schema (Supabase)
* `Table: raw_corpus` (id, content, source, scraped_at)
* `Table: processed_tensors` (id, raw_id, tensor_array, token_count)
* `Table: inferences` (id, request_payload, prediction, confidence, timestamp)
* `Bucket: r_analytics_plots` (storage for .png files generated by R)

## 4. Deployment Architecture
* **Source Control:** GitHub
* **CI/CD:** Bash scripts running inside GitHub Actions.
* **Containerization:** 10 distinct `Dockerfiles`, orchestrated locally via `docker-compose` and deployable to an AWS ECS or Kubernetes cluster.
* **Frontend Hosting:** Vercel (Next.js automatically connected to the GitHub repository).
* **Database Hosting:** Supabase Managed Cloud.
